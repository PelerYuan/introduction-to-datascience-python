# 《Data Science: A First Introduction with Python》中译本 —— 翻译规范（STYLE GUIDE）

> 本文件是全部翻译与审校工作的**唯一权威规范**。任何与此文件冲突的直觉、习惯或"更好的说法"一律以本文件为准。
> 版本：v1.0（冻结版）。如需修改，必须由总协调人统一修改并通知所有 agent。

---

## 0. 一句话总纲

> **译文要读起来像一位中文统计学教师在用中文写教材，而不是像一台机器在逐词搬运英文。**

判定标准（自检清单）：

1. 把译文单独拿给一个没看过英文原文的中文读者读，**读不出"这是翻译的"**。
2. 中文语序、断句、指代符合中文习惯；**不保留英文的从句套从句结构**。
3. 术语前后一致、首见处规范；专有名词、代码、公式、交叉引用**零改动**。
4. 信息**不多不少**：不添加原文没有的解释，不省略原文有的逻辑连接。

## 1. 读者与语域

- **目标读者**：大学低年级本科生、转行学习者、自学者。多数人不具备统计或编程背景。
- **语域**：严谨但亲切的教学口吻。原文大量使用 "we will"、"let's"、"you can"——这是**教材惯用的引导式第一人称**，中文应处理为"我们将""我们来看看""你可以"，**不要**生硬地译成"让我们"堆叠，也**不要**改成无人称的说明书腔。
- **称呼**：正文用"你"（原文用 you），不要用"您"（过于客套，与非正式教学语气不符），不要用"读者"（生硬）。
- **不使用口语化网络语**（"搞定""get 到""离谱"），也不使用学术黑话（"范式跃迁""赋能"）。

## 2. 「AI 味 / 翻译腔」黑名单（最重要的一节）

以下是最容易出现的机器翻译痕迹。**每一条都必须检查。**

### 2.1 词汇层面

| 禁止 | 应改为 | 说明 |
|---|---|---|
| 让我们……（连续出现） | 我们来看看……／接下来……／（直接陈述） | 原 "Let's" 在中文教材里通常直接省略主语 |
| 一个……的……（冗长定语） | 直接陈述 | "a data set that contains 214 languages" → "该数据集包含 214 种语言"，而非"一个包含了 214 种语言的数据集" |
| 这是值得注意的 | 值得注意的是／请注意 | 保留，但**全章不超过 1–2 次** |
| 不仅……而且……（滥用） | 拆分或改用"并且""同时" | 英文 not only...but also 多数情况下直译很生硬 |
| 通过……的方式 | 用……／借助……／直接改写 | "by using X" → "使用 X" |
| 在……的情况下 | 如果……／当……时 | |
| 进行一个……的操作 | 直接说动作 | "perform an analysis" → "进行分析"（可），"进行一个分析的操作"（禁） |
| 具有……的特点 | 是……／具有……（简） | |
| 基于……的基础上 | 基于……／在……基础上 | 语义重复，禁止 |
| 被广泛地认为 | 普遍认为 | |
| 相关的内容／相关的数据 | 直接说"内容""数据" | 删掉无意义的"相关" |
| 各种各样的 | 各种 | |
| 非常重要的 | 很重要／至关重要 | |
| 与此同时同时 | — | 禁止同义堆叠 |
| 让我们假设 | 假设 | |
| 从而使得 | 从而／使得（二选一） | |
| 由于……的原因 | 由于……／因为…… | |
| 通过本章的学习，读者将能够 | 学完本章后，你将能够 | 见 2.2 |

### 2.2 句式层面

- **禁止照搬英文被动语态。** "The data were collected by..." → 中文优先主动："这些数据由……收集"或"……收集了这些数据"。
- **禁止一句到底的长句。** 英文一句 60 词的句子，中文通常要拆成 2–3 句。拆句是**允许且鼓励**的，只要逻辑连接词补足。
- **禁止 "的" 字连用超过两次**（"数据的分布的特征的图"）。
- **禁止把英文的代词直译。** 英文的 it/they/this 在中文里往往该省略或还原成名词。中文里 "它" 出现太频繁一定有问题。
- **禁止保留英文的介词短语后置。** "the mean of the population" → "总体均值"，而非"总体的均值"式的层层嵌套。
- **禁止 "当……的时候"**（"当"本身已含"的时候"）。

### 2.3 标点与排版层面

- 中文句内一律用**全角标点**：`，。：；？！（）""''`。
- **逗号用 `，`，不要用 `、` 代替逗号**；`、` 只用于并列词项（"均值、中位数和众数"）。注意：英文 "A, B, and C" 译为 "A、B 和 C"（最后一项用"和"或"以及"，前面用顿号）。
- 中文与**西文/数字/行内代码之间加一个半角空格**：`使用 pandas 读取数据`、`共有 214 种语言`、`调用 read_csv 函数`。
- 中文标点与西文之间**不加空格**：`数据（data frame）`、`均值。`。
- 英文原文中的 `&mdash;`（破折号）译为中文破折号 `——`，不要保留 `&mdash;` 实体（**例外**：见第 4 节，若它出现在受保护结构中则不动）。原文用 `&mdash;` 包裹插入语时，中文通常改用 `——` 或括号。
- 引号统一用中文弯引号 `""`、`''`。行内代码 `` `x` `` 内部保持半角。
- 数字与单位、年份保持半角阿拉伯数字。
- 省略号用 `……`。

### 2.4 「不添加、不删减」原则

- **不要**在译文里添加原文没有的"小结""提示""解释"。
- **不要**为了通顺而删掉原文的限定词（only, at least, approximately, roughly, typically, in general, for example）。这类词是教材严谨性所在。
- **不要**把原文的举例（for example, e.g.）扩写成完整段落。
- 原文中作者明显的幽默/口语（如 "get your hands dirty"、"Sadly"）应译出**同等语气**，不要抹平成中性腔调："get your hands dirty right from the start" → "从一开始就动手实干"。

## 3. 术语处理

### 3.1 强制术语表

- **必须使用 `GLOSSARY.md` 中规定的译法**，不得自行另创译名。
- 若遇到 `GLOSSARY.md` 未收录的反复出现的术语：先在脑中判断是否属于"领域术语"，若是，则**在译文末尾的 `<<TERM>>` 段中登记**（格式见第 6 节），并采用一个合理译法；审校环节会统一收敛。
- 同一术语在全书中必须**逐字一致**（包括"数据框"不能一处写"数据框"、另一处写"数据帧"）。

### 3.2 首见加注

- 领域术语**首次出现**时，若中文译名与英文原词差异较大或读者可能对照英文资料，采用：`中文译名（English term）`。
  例：`整洁数据（tidy data）`、`自助法（bootstrap）`、`图形属性映射（aesthetic mapping）`。
- **每个术语在同一章内只加注一次**，全书中首次出现的那一章负责加注；若不确定是否为全书首见，**按章节首见处理即可**（允许少量重复，优于漏注）。
- 代码标识符（`read_csv`、`pandas`、`loc`）**永远不翻译、不加注**，直接在中文句中当英文词用。
- 数学符号、变量名（`x`、`y`、`β`）不翻译。

### 3.3 术语与代码的边界

- 原文说 "the `read_csv` function（读取 CSV 文件的函数）" 时，`read_csv` 不动，函数说明文字翻译。
- 原文直接用人话指代函数时，若中文习惯保留英文就保留：
  - 可译：`合并（merge）`、`分组（groupby）`——即"动作名（函数名）"。
  - 保持英文：`DataFrame`、`Series`、`k-means`、`altair`、`scikit-learn`。
- **禁止**把 `pandas` 译成"熊猫"，`Series` 译成"序列对象"之类臆造名。

## 4. 结构保护（硬性规则，违反即为废稿）

翻译时**只改"给人读的自然语言文本"**。以下内容逐字节保持原样：

1. **YAML front matter**：文件开头的 `--- ... ---` 整块（`jupytext:`、`kernelspec:` 等）**一个字都不改**。
2. **显式标签**：`(intro)=`、`(fig:02-obs)=`、`(08:puttingittogetherworkflow)=` 等**原样保留**（含括号与等号，含 `:`）。
3. **代码单元格**：```
```{code-cell} ipython3` … ``` 整块（含 `:tags: [...]` 选项、Python 代码、注释）**逐字节保留**。
4. **普通代码围栏**：``` ```python … ``` ```、``` ```bash … ``` ``` 等整块保留。
5. **行内代码**：`` `read_csv` `` 内容不动。
6. **MyST 指令外壳**：```{figure}```、```{note}```、```{index}```、```{list-table}```、```{table}```、```{bibliography}``` 的**指令名与选项行**（`:name:`、`:header-rows:`、`:figclass:`、`:width:` 等）不动；只翻译其中的**可见文本**。
   ```
   ```{figure} img/intro/canada_map.png
   ---
   name: canadamap
   ---
   加拿大地图          ← 只有这一行是译文
   ```
   ```
7. **角色 / 引用**：`{numref}`…``、`{cite:p}`…``、`{glue:text}`…`` 的**花括号部分与反引号内的标识符**不动。
8. **交叉引用的自定义文字**要翻译：
   - `{numref}`Chapter %s <intro>`` → `` {numref}`第 %s 章 <intro>` ``
   - `{numref}`Chapters %s <reading>`` → `` {numref}`第 %s 章 <reading>` ``（中文不分单复数，统一"第 %s 章"）
   - `{numref}`fig:05-scatter`` → **不动**（前缀由 `_config.yml` 的 `numfig_format` 统一渲染为"图 %s"）
   - `{numref}`tab:05-…``、`{numref}`08:puttingittogetherworkflow`` → **不动**
9. **数学**：`$...$`、`$$...$$`、`\begin{}...\end{}` 内部不动。
10. **Markdown 链接与图片**：`[文字](url)` 只翻译 `文字`，`(url)` 不动；`![alt](path)` 只翻译 `alt`（若 alt 是文件名则整体不动）；`<img src="...">`、`<a href="...">` 的属性不动，只翻译可见文字。
11. **单元格分隔符 `+++`**：单独一行的 `+++` 保留。
12. **表格分隔**：MyST list-table 中 `* -`、`  -` 的**结构与缩进层级**必须完全保持，只改其后的文字。
13. **`{index}` 内容**：需要翻译（它们是索引词条），但保留 `;` 分隔符与 `see:` 前缀结构：
    - `{index} data frame; definition` → `{index} 数据框; 定义`
    - `{index} see: data frame; DataFrame` → `{index} see: 数据框; DataFrame`
    - 注意 `see:` 是关键字，保留英文。
14. **HTML 实体**：`&mdash;` 在正文中译为 `——`；但若位于受保护结构内则不动。
15. **文件名、路径、URL、包名**不动。
16. **`{glue:text}` 之类由构建期求值的角色**：绝不改动，也绝不在其前加空格以外的字符。

> **自检方法**：翻译完成后，把"英译中结构骨架"对照检查一遍——指令名、标签、代码块内容必须 100% 相同。

## 5. 分节细化要求

### 5.1 标题
- 标题翻译要**短而准**，不要因为求准确而变长。
- `## Chapter learning objectives` → `## 本章学习目标`
- `## Overview` → `## 概述`
- 句首大写风格在中文不存在，忽略。
- 标题末尾不加句号。

### 5.2 学习目标列表
- 原文 `By the end of the chapter, readers will be able to do the following:` → `学完本章后，你将能够：`
- 列表项以动词开头，用中文动词短语："识别（Identify）……"等，保持 `-` 与缩进。
- 嵌套的代码标识符列表（如 `- `melt``）**不动**。

### 5.3 图表标题（figure caption）
- 是完整句子，**末尾加句号**。
- 保持术语一致（"数据框""观测""变量"）。
- 若原文提到颜色（"colored yellow"），译为"用黄色标出"。

### 5.4 注释框（`{note}` / `{tip}` / `{warning}`）
- 指令名不动，内部段落翻译。
- 保持原文的语气强度（warning 要译出警示感）。
- 换行位置可以重排（中文排版不同），但段落划分（空行）必须与原文一致。

### 5.5 表格
- `* - ` 后的表头文字翻译；单元格中的代码标识符保留。
- 单元格内的完整句子按普通句子处理。

### 5.6 术语首见与"定义"句
- 原文形如 "**variable:** a characteristic, number, or quantity that can be measured." 的定义列表：
  → "**变量（variable）：** 可以被测量的一种特征、数值或数量。"
- 保持 `**加粗**` 的加粗范围。

### 5.7 引用与参考文献
- `{cite:p}` 系列一律不动。
- 原文正文中顺带提到的书名/文章名，译成中文名并在括号内保留英文原名（如果原文有引号）：
  `*Canadian Geographic*'s article, "Mapping Indigenous Languages in Canada"` → `《Canadian Geographic》杂志的文章 "Mapping Indigenous Languages in Canada"`（**英文报刊/文章名保留英文并改用书名号**，因为无通行中文译名）。

### 5.8 代码注释
- **Python 代码中的注释不翻译**（属于代码块，硬性保留）。
- 但若原文在正文中引用了注释文字，正文照译。

## 6. 输出格式契约（每个翻译 agent 必须遵守）

- 只输出**译文正文**，不输出解释、前言、总结、代码围栏包裹的全文件。
- 保留原文的**空行结构与块顺序**（包括 `+++`）。
- 若发现原文中反复出现而 `GLOSSARY.md` 未收录的领域术语，**不要**在正文里加脚注，而是在文件末尾追加一个区块：

```text
<<TERM>>
English term = 中文译法
<<END>>
```

  - 每个文件最多登记 15 条；已在 `GLOSSARY.md` 中的不要登记。
  - 没有新增术语就不输出该区块。

## 7. 高频句式对照样例（照此风格写）

| 英文原文 | 好的译法 | 差的译法（禁止） |
|---|---|---|
| This chapter provides an introduction to data science and the Python programming language. | 本章介绍数据科学与 Python 编程语言。 | 本章提供了一个对于数据科学和 Python 编程语言的介绍。 |
| The goal here is to get your hands dirty right from the start! | 我们的目标是让你从一开始就动手实干！ | 这里的目标是让你从一开始就弄脏你的手！ |
| In the following chapters, we will dig into each of these steps in much more detail. | 后续各章会逐一深入讲解这些步骤。 | 在接下来的章节中，我们将会以更多的细节来挖掘这些步骤中的每一个。 |
| but for now, let's jump in to see how much we can do with data science! | 不过现在，我们先直接上手，看看用数据科学能做多少事情！ | 但是现在，让我们跳进去看看我们能用数据科学做多少事情吧！ |
| Suppose we want to know which are the most common. | 假设我们想知道哪些语言最为常见。 | 假设我们想要知道哪些是最常见的。 |
| Data science cannot be done without a deep understanding of the data and problem domain. | 要做好数据科学，就必须深入理解数据和问题所在的领域。 | 数据科学不能在没有对数据和问题领域的深入理解的情况下被完成。 |
| If your data are biased, then your results will be biased! | 数据有偏差，结论就会有偏差！ | 如果你的数据是有偏差的，那么你的结果将会是有偏差的！ |
| Every good data analysis begins with a *question*. | 每一次出色的数据分析都始于一个*问题*。 | 每一个好的数据分析开始于一个问题。 |
| Carefully formulating a question as early as possible in your analysis will guide your overall approach. | 在分析中尽早、审慎地提出问题是至关重要的，它会决定你的整体思路。 | 在你的分析中尽可能早地仔细表述一个问题将指导你的整体方法。 |
| we need to introduce a few technical terms | 我们需要先引入几个技术术语 | 我们需要介绍一些技术上的术语 |
| There are 13 entities in the data set in total, corresponding to the 13 rows. | 该数据集共有 13 个实体，对应 13 行。 | 在这个数据集中有总共 13 个实体，对应于 13 行。 |

## 8. 审校（reviewer）验收标准

审校 agent 必须逐项给出结论。任一"不通过"即需修复：

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| R1 | **结构完整性** | 指令名、`(label)=`、代码块、角色、`+++`、front matter 与英文原文**逐字节一致**（除允许翻译的可见文本外） |
| R2 | **信息完整性** | 无遗漏句子/从句/限定词；无新增说明 |
| R3 | **术语一致性** | 全部命中 `GLOSSARY.md`；同章内同词同译 |
| R4 | **准确性** | 无错译、无歧义、指代清晰（尤其代词、比较级、否定范围） |
| R5 | **中文自然度** | 无第 2 节黑名单现象；朗读一遍无卡顿；无"的"字连用 |
| R6 | **标点排版** | 全角标点；中西文间空格；首见术语加注规范 |
| R7 | **可读性** | 目标读者（无背景本科生）能读懂，不需要看英文原文 |
| R8 | **代码零改动** | 代码单元格与行内代码逐字节一致 |

审校输出格式：

```text
## 结论：通过 / 不通过
## 必须修复（逐条给出：行号或原文片段 → 现译 → 建议译法）
## 术语登记（<<TERM>> 段中的条目是否采纳）
```

## 9. 术语表（GLOSSARY.md）约定

- 格式：`English | 中文 | 备注`
- `备注` 用于：是否首见加注、是否保留英文、特殊情况。
- 标签 `[保留英文]` 表示该词在正文中一律不翻译。
