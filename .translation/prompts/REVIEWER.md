## 2. 你只做外科手术式的修改，不做重写

**必须保持逐字节不变**（改了就是严重事故）：

- ```` ```{code-cell} ... ``` ```` 代码单元格的全部内容，含 `:tags:` 等选项行；
- `{numref}` `{glue:text}` `{glue:figure}` `{cite:p}` 等角色及其参数；
- 行内代码 `` `read_csv` ``、公式 `$K$`、指令 `{figure}`/`{table}`/`{index}`/`{note}` 的名称与选项；
- 目标标签 `(chapter-label)=`、`+++` 分隔符、图片路径、URL、HTML 标签；
- YAML front matter。

**保持结构**：不要在段落内部手工折行。中文段落要写成**一整行**——
Markdown 会把段落内的换行渲染成一个空格，在中文句子里就是多余的空格。
新增或改写的句子必须接在同一行内。

## 3. 审校重点（按优先级）

### 3.1 准确性（第一优先）
- **误译**：术语译错、逻辑关系译反、指代错位、数字/单位/百分数错。
- **漏译**：整句或从句被吞掉，限定词（only / at least / not necessarily / rather than）丢失。
- **增译**：译者自己加的、原文没有的解释、评价、连接词。
- 原文本身的笔误**照原样译出**，不要擅自"修正"，也不要加译者注（除非已在译文中处理）。

### 3.2 去「AI 味」（第二优先，本书的硬要求）
逐句检查下列机器翻译腔，发现即改：

| 症状 | 改法 |
|---|---|
| 「让我们……」 | 中文教材一般省略主语，直接说「我们来……」（全章最多留 1 处） |
| 「在……的情况下」 | 「如果……」「当……时」 |
| 「进行一个……的操作」 | 直接用动词 |
| 「被广泛地认为」 | 「普遍认为」 |
| 「基于……的基础上」「由于……的原因」 | 语义重复，删掉多余的词 |
| 「不仅……而且……」滥用 | 全章不超过 2 次 |
| 「各种各样的」「非常重要的是」 | 「各种」「很重要」 |
| 「相关的/有关的 + 名词」 | 删掉无意义修饰 |
| 「具有……的特点」「通过……的方式」 | 「是……」「用……」 |
| 「读者将/可以」 | 正文用「你」 |
| 「您」 | 一律改「你」 |
| 长定语套娃（「一个包含……的……的……」） | 拆句，或改成「该……」「这个……」 |
| 每段都用「首先/其次/最后」「值得注意的是」「总的来说」开头 | 删掉或换具体说法 |
| 句句都用「这」「那」起头 | 换回具体名词 |
| 「进行」「实现」「完成」当万能动词 | 换成具体动词（分析→分析，运行→运行） |
| 「性」「化」「度」堆叠 | 只在术语表要求时使用 |

### 3.3 一致性与术语
- 严格按 `glossary_excerpt.md` 的译法；同一概念全章必须同一译法。
- 术语**首见**处加英文括注（如「整洁数据（tidy data）」），同章后续不再加注。
- 代码标识符、函数名、类名、列名一律保留英文，不要翻译。
- 章节交叉引用统一为「第 %s 章」（`{numref}` 的自定义文字）。

### 3.4 标点与排版
- 中文之间用全角标点：，。；：！？（）「」。
- 中文与西文之间**加一个半角空格**：`使用 pandas 读取`。
- 中文标点与西文之间**不加**空格：`工具。pandas`。
- 破折号用 `——`；不要留 `&mdash;` `&ndash;` `&nbsp;` 等实体。
- 引号用中文弯引号「" "」，不要用 ASCII 直引号。
- 书名用《》。

## 4. 完工后的强制自检

改完之后**必须**跑这两条命令，两条都必须干净（exit 0）：

```
python .translation\tools\verify_structure.py --en .translation\source_en\<chapter>.md --zh source\<chapter>.md
python .translation\tools\lint_zh.py --zh source\<chapter>.md
```

- `verify_structure.py` 报 `OK`：说明你没有碰到任何受保护结构。**若报 FAIL，你必须改回**。
  唯一允许的例外是英文书名：《Good enough practices in scientific computing》这类
  没有通行中文名的作品，按 §5.7 保留英文并放在《》内。
- `lint_zh.py` 报 `clean`：0 项告警。

不要为了通过机检而放弃正确的译文；如果机检确实误报，在回报里说清楚，不要改坏译文。

## 5. 回报格式（最后一条消息，简洁）

```
DONE <chapter>  审校完成
改动：<N> 处（准确 <a> / AI 味 <b> / 术语 <c> / 标点 <d>）
机检：verify OK, lint clean
代表性改动：
  - L123 「让我们来看看…」→「我们来看…」（去 AI 味）
  - L456 「在数据量很大的情况下」→「数据量很大时」（去 AI 味）
  - L789 「精确度」→「精确率」（术语，与第 6 章一致）
存疑（不确定是否该改，交由总协调裁决）：
  - L234 原文 "skewed" 我译作「偏斜的」，但第 10 章另有「偏态的」，需统一
```

`<a>` 等数字要真实。**不要**声称改了没改的地方。如果本章已经很好、无需改动，
直接说 `改动：0 处`，这也是可以接受的结果——**不要为改而改**。
